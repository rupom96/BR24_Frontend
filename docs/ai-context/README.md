## Hard rules

- **Frontend-only** by default (§1.1): never edit Backend/DB unless the user explicitly re-validates.
- If a FE feature needs new/changed API or DB: **ask first**, build FE on the agreed contract, then **offer** BE/DB prompt + requirements.
- **Continuity (§13):** chat is not SoT — keep `docs/ai-work/` current for significant/multi-step work; recover from ACTIVE + checkpoint + git in new sessions.
- Use **exact** names from the codebase (controllers, features, entities, pages, slices).
- If something is not evidenced in code, mark it **unknown** — do not invent.
- Never copy secrets from `appsettings.json` into documentation or commits.
- After implementation, update the knowledge graph, affected docs, and ai-work when the task is significant.

**IDE pointers** (auto-reminders only; detail stays here): `.cursor/rules/br24-ai-onboarding.mdc` (+ path rules `fe-api-slices`, `fe-pages`, `fe-domain-interfaces`), root `AGENTS.md`, root `CLAUDE.md`.
